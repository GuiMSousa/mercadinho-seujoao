## Backup do banco

Em produção, use o arquivo e o compose de produção (`-EnvFile .env.production -ComposeFile compose.prod.yaml` no `.ps1`, ou `ENV_FILE` e `COMPOSE_FILE` no `.sh`). O agendamento e a restauração da produção estão em [deploy.md](deploy.md#5-backup-automático). Abaixo, o uso no desenvolvimento.

Os scripts `scripts/backup-db.ps1` (Windows) e `scripts/backup-db.sh` (Linux, macOS ou Git Bash) rodam `pg_dump` dentro do contêiner do Compose (serviço `postgres`) e gravam um arquivo comprimido em `backups/<banco>-<data-hora>.dump`. A pasta fica fora do Git (`.gitignore`), porque guarda dados pessoais e financeiros.

- **Como funciona:** o dump é feito dentro do contêiner, conferido com `pg_restore --list` e copiado com `docker cp`, para nenhum shell alterar os bytes. Só o usuário e o nome do banco são lidos do `.env.local`; nenhuma senha passa pelo script ou pela tela. Os dumps com mais de 30 dias são apagados (`-KeepDays 30` / primeiro argumento do `.sh`).
- **Rodar à mão:** `pwsh -NoProfile -File scripts/backup-db.ps1` ou `sh scripts/backup-db.sh`. Exige o banco no ar (`npm run db:up`).
- **Agendar no Windows** (todo dia às 22h30, como o usuário logado):
  `schtasks /Create /SC DAILY /ST 22:30 /TN "Mkt Control - backup" /TR "pwsh -NoProfile -File C:\mercadinho_seujoao\mercadinho-seujoao\scripts\backup-db.ps1"`
- **Agendar no Linux:** `crontab -e` com `30 22 * * * cd /caminho/do/projeto && sh scripts/backup-db.sh >> backups/backup.log 2>&1`.
- **Fora do PC:** copie `backups/` para outro disco ou nuvem; um backup no mesmo disco não sobrevive a uma falha dele.
- **Restaurar** (substitui os dados do banco de desenvolvimento; faça depois de um backup novo):
  1. Pare o `npm run dev` e feche Drizzle Studio e `psql`: a troca de nome do banco exige zero conexões.
  2. Guarde o contêiner em `c`: `c=$(docker compose --env-file .env.local ps -q postgres)` no Git Bash, `$c = docker compose --env-file .env.local ps -q postgres` no PowerShell.
  3. `docker cp backups/<arquivo>.dump "${c}:/tmp/restore.dump"`.
  4. Rode a linha `docker exec … sh -c '…'` do bloco "Restaurar" de [deploy.md](deploy.md#5-backup-automático), trocando `mkt-control-prod-postgres-1` por `"${c}"`. Ela restaura num banco à parte e só troca o atual depois do sucesso. Não use as linhas com `compose.prod.yaml` daquele bloco: elas param a demo de produção.
  5. Só depois de `RESTAURADO`, volte ao `npm run dev`.
- **Verificado em 2026-11-05:** os dois scripts geraram dumps válidos do banco de desenvolvimento (14 tabelas com dados listadas pelo `pg_restore --list`).
